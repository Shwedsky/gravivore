## Изготовление и наблюдаемое соответствие

Перестроен один Capacitor Field. Три камеры разной высоты объединены общей ступенчатой опорой, силовой шиной, изоляторами и возвратными коммуникациями. Собственные корпуса имеют вложенные основания, скосы, броневые секции, стяжки и механические сопряжения. Четыре трансформатора, шкаф распределения, сервисная площадка и лестницы раскрывают функцию установки. Пол составлен из крупных нагрузочных плит; по краям и поперёк передней части проходят настоящие углубления с решётками. Старый `deck()` R2 не использован для нового сектора.

Основные конструкции — новые проектные модели. Quaternius и Molten дают вспомогательные трубные стойки, держатели, точки обслуживания и консоль. Их исходные UV сохранены; Molten использует точные байты исходной палитры, Quaternius — ранее промотированные trim-карты R1. Лицензии CC0, записи архива/entry/SHA256 и редактируемый Blender приложены. Масштабирование доноров равномерное. Основные машины не сжаты по трём осям.

Графит, окрашенная оболочка, металл, настил, керамика и энергетические участки имеют разные материалы. Собственные UV повторяют поверхность раз в метр. Эмиссия ограничена рабочими электродами и сигналами. Геометрические углубления, толщина и сопряжения остаются видны без свечения.

Одна рабочая follow-камера: offset `(3.4, 19.8, -13.6)`, FOV `48°`, высота цели `3.2 м`. Пять нормальных позиций сняты этой камерой: вход, бой, подход, край, обратный выход. Каждая пара UI/no-UI получена при одном положении камеры и одном игровом tick. Высокие короны могут выходить за верх кадра при подходе; основание, соединения и рабочие камеры продолжают показывать функцию. На сравнении APK 50 оставлен его исходный ракурс и явно подписан.

Наблюдаемое улучшение — иерархия трёх камер, общий силовой узел, обслуживаемые машины и геометрическая глубина пола вместо повторяющегося небольшого настила. Это оценка приложенных игровых кадров Editor. Плотность деталей и световая драматургия иллюстрации воспроизведены частично; художественное принятие владельцем на Android ещё не получено. Число мешей и зелёные тесты не являются художественным gate.

## Техническая работоспособность

Сохранены Actor V2 и движущийся бипедальный G-0. Runtime, archetype IDs, HP/урон/дальности/интервалы, награды, оборудование, задания, ремонт, прогрессия и схема сохранений сохранены. Изменены четыре явных footprint/blocker volumes сектора; миникарта получает их из той же layout authority. Декоративный prefab не содержит Collider или MonoBehaviour. Остальные модели секторов не переработаны; общие камера и рендер изменяют их вид как игровой контекст.

URP Renderer теперь содержит настоящий `postProcessData` из установленного пакета. Контракт: Linear PBR, HDR, ACES, Bloom intensity `0.12`, threshold `1.25`, без дополнительных Renderer Features. Существующие проверки UI/материалов/шейдеров/Android API сохранены. Добавлен отказ валидатора при отсутствии ресурсов и проверка упаковки/компиляции Bloom, UberPost, ACES и Bloom LQ при сборке.

Постобработка действительно меняет изображение: одинаковая камера и tick, переключение только `renderPostProcessing`; 518400 изменённых пикселей из 518400, средняя абсолютная разница каналов 26.76/255. Это проверка исполнения всего post-processing pass, а не изолированная оценка Bloom. PNG сняты в sRGB SDR, без ретуши.
