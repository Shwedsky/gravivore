# Android packaging environment

The normal repository Dev build was executed for the actual Bootstrap and production Chapter scenes. It stalled in Android SDK detection while `sdkmanager --list` waited for remote package manifests. API 34/35/36 and build-tools/platform-tools 36.0.0 were already installed. No final APK was claimed from that stalled attempt; only this task's verified Unity build process and its children were stopped.

A private mirror of the installed SDK was copied under the workspace's ignored `.utmp/architecture-sdk55`. Only the mirror's package-list command is wrapped: `--list` delegates to the official tool's `--list_installed`, reading the genuine copied package XML. Other commands delegate to the original tool. No SDK package/version records are fabricated, no package is downloaded/installed, and the original installed SDK manager's SHA-256 is retained and unchanged. The installed-only option is part of the [Android SDK manager implementation](https://android.googlesource.com/platform/tools/base/+/86cf6e5d2c6a6c4d044afb2ac21d952848f39f26/sdklib/wrappers/sdkmanager.sh).

`ArchitectureAndroidBuild.BuildWithInstalledSdk` temporarily selects that mirror and invokes the unchanged repository `Gravivore.Editor.Build.AndroidBuild.BuildDev`. It restores the prior functional SDK selection in `finally` and writes the before/after receipt. Unity documents the [SDK root selection API](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Android.AndroidExternalToolsSettings-sdkRootPath.html). The retry completed SDK detection in approximately 4.8 seconds.

This is a build prerequisite workaround, not a standalone art-proof APK. Gameplay scripts, production scenes, scene collision binding, original encounter state/configuration and the new environmental route remain in the build. APK success/hash/version are recorded only after an actual package exists and the build finishes. SDK binaries and APKs remain local/ignored, outside runtime content and the public repository.
