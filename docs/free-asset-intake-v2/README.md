# Free Asset Intake V2 — vetted reference library

Status: **REFERENCE / EVIDENCE, NOT CURRENT IMPLEMENTATION INSTRUCTIONS**

This folder records the completed V2 discovery, provenance, technical inspection and USE/DONOR/REJECT decisions. It is intentionally retained because those measurements and license decisions are useful.

Do **not** use the old worktree paths in this folder as current asset-source instructions. Current paths are defined only by `docs/ASSET_SOURCE_OF_TRUTH.md`.

Historical V2 execution found 26 actual art payloads plus one owner concept image, measured 1171 canonical FBX models, captured representative samples, and produced the Chapter01 selection/replacement recommendations now used as reference evidence.

The original V2 raw downloads lived in a specific Codex worktree root (`98_unclassified/`, `00_reference/`) while the planned V1 intake tree also existed. Those locations are frozen historical caches. New assets go to `ExternalAssetIntake/Current/` instead.

Expected historical states were 27 FOUND, one missing armored-pipes source and 11 Meshy subscription skips. TechLab licensing and Tiago/Icons8 mixed-rights remained unresolved; do not silently promote them without a fresh item-level license review.

## Useful review order

1. `RECOMMENDED_ASSET_STACK.md` and `CHAPTER01_REPLACEMENT_MATRIX.md` — prior selection rationale and known gaps.
2. `ASSET_SELECTION_MATRIX.md` and `UNFILLED_ART_GAPS.md` — source/item decisions and custom-work needs.
3. `ASSET_ZOO_REPORT.md`, `TECHNICAL_ASSET_INVENTORY.csv`, `EVIDENCE_MANIFEST.json` — measured facts and preview limits.
4. `SOURCE_DISCOVERY_REPORT.md`, `SOURCE_RESOLUTION.json`, `ASSET_PROVENANCE_RESOLVED.csv`, `ATTRIBUTION_DRAFT.md`, `VALIDATION_REPORT.md` — provenance and validation evidence.

## Important current interpretation

- The V2 library does not define the game's style; `docs/CURRENT_VISUAL_TARGET.md` does.
- A source graded USE/DONOR is still subject to current concept-fit and production-quality review.
- Old low-poly/mobile-friendly labels do not make an asset visually suitable.
- Raw third-party packages remain subject to public-repository redistribution restrictions.
- If the selected content has already been promoted into current runtime assets, use the tracked production asset rather than rescanning this historical cache.

The original reproduction workflow belongs to the completed intake stage and has been moved/retained as history, not as the default workflow for new Codex passes.
