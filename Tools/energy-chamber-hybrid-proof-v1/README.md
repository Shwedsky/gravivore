# Isolated Energy Chamber proof tools

Run from this task's worktree, never the concurrent gameplay checkout. Unity 6000.3.0f1 and Blender 5.2 are available on the owner machine. No new package is required.

1. `prepare.py` with the existing Python runtime: locate only the two canonical owner-local CURRENT ZIPs, extract named candidates/license bytes into ignored inspection scratch, retain exact hashes. It does not import packs into Unity.
2. Blender batch `--python Tools/energy-chamber-hybrid-proof-v1/inspect.py`: open actual FBX geometry, record material/UV declarations, dimensions and triangles, render each selected candidate's real geometry. These source geometry views use Workbench; final material acceptance uses Unity.
3. Blender batch `--python Tools/energy-chamber-hybrid-proof-v1/author.py`: author project-owned silhouette geometry, save editable `.blend`, export four FBXs and promote only the two selected raw service FBXs plus license evidence. Existing machinery remains referenced.
4. `run_unity.ps1 -Action Author`: compile editor-only proof builder and create the materials, master node, installation prefab and dedicated scene. Assembly wrappers preserve native FBX unit/axis transforms. Current camera, G-0 and PBR donor dependencies are read, not intentionally modified.
5. `run_unity.ps1 -Action Capture`: produce all seven review views through Unity URP, including emission-off material clones and a true player-position camera anchor. No post-capture image editing. Captures are 1080 × 1920 for actual gameplay views.
6. `run_unity.ps1 -Action EditMode`, `PlayMode`, `ProjectValidate`, optionally `Validate` / `Compile`: run appropriate checks. Full EditMode suite; isolated scene smoke in PlayMode.
7. `run_unity.ps1 -Action Android`: export the exact saved proof scene and its native visual dependency closure into ignored `Builds/EnergyChamberStage/`, then compile/build that standalone project using `StageBuild.cs`. The exporter rejects any project C# or DLL dependency. The standalone builder checks missing scripts/materials, camera lens, G-0 scale and presentation-only authority before the dev ARM64 IL2CPP build. Package `com.gravivore.energychamberproof`, output `Builds/Android/gravivore-energy-chamber-proof-v1-dev.apk`. Production Chapter build callbacks require unrelated Chapter content and reject a one-scene proof in the full project; this separate project gives the proof its appropriate validation without changing those callbacks or bypassing them in the production build.
8. `record_origins.py`: generate exact source-to-component/runtime path records.
9. After Unity finishes, use `restore_unity_reserialization.ps1` to restore only automatic tracked reserialization **outside** the dedicated proof paths in this otherwise clean isolated worktree. It verifies the branch, root and every target path. Do not stage generated project settings or unrelated audit rewrites. `verify_delivery.py` refuses delivery if such tracked differences remain. It checks additive scope, promoted model hashes, passing test XML, APK package/ABI and one-scene packaging, and writes the complete changed-file list and delivery receipt.

Commands may require execution outside the process sandbox to connect to the installed Unity Licensing Client. Never terminate another user's Unity process. Logs are retained locally under the proof verification folder and ignored; result XML/JSON and final screenshots are tracked.

The proof has no new runtime MonoBehaviour and no interaction/movement/gameplay authority. Scene cameras are static review anchors; player-follow evidence reproduces the current follow camera's settled transform formula. G-0's original presentation is referenced unchanged at unit scale. APK device acceptance remains an owner review step.
